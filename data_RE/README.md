# RE 漏洞检测实验：50 条分层样本

状态：样本已冻结，实验计划为初稿。

本目录保存第一批 RE（Reentrancy，重入）漏洞检测实验的 50 条样本、源码副本、抽样脚本和校验结果。实验目标是在同一个小模型和同一批源码上比较三种策略：

1. Qwen 直接阅读完整源码，给出判断、理由和漏洞行原文；
2. 使用固定关键词 `balance` 和 `call` 定位候选代码，再由 Qwen 判断；
3. 先让 Qwen 生成关键词，再用关键词定位候选代码，最后由同一个 Qwen 判断。

## 1. 数据来源

样本来自冻结的 `DIVE_balanced` 数据集，仅筛选 `task=RE` 的记录。

| 输入 | 路径 |
|---|---|
| 任务清单 | `04-datasets/dive/splits/DIVE_balanced/dataset/manifests/task_manifest.csv` |
| 源码清单 | `04-datasets/dive/splits/DIVE_balanced/dataset/manifests/source_manifest.csv` |
| 原始源码 | `04-datasets/dive/splits/DIVE_balanced/dataset/sources/` |

原始 RE 数据共有 398 条记录，其中正样本 207 条、负样本 191 条。本目录中的 50 条是为比较源码复杂度而设计的分层样本，不代表原始数据的自然比例。

## 2. 冻结抽样方案

复杂度按冻结源码文件的物理行数划分：`<100`、`100–300`、`>300`。抽样随机种子为 `42`，六个“复杂度 × 标签”单元分别抽样。

| 复杂度 | 总数 | 正样本 | 负样本 |
|---|---:|---:|---:|
| `<100` 行 | 15 | 8 | 7 |
| `100–300` 行 | 15 | 5 | 10 |
| `>300` 行 | 20 | 12 | 8 |
| **合计** | **50** | **25** | **25** |

复杂度分层只用于实验分析，不是数据集原始标签。后续若使用 `prompt_source`，应继续使用保留换行的注释移除版本，并记录其哈希。

## 3. RE 类型定义

正式运行前先冻结以下 RE 定义，并将同一段文字放入三种方法的判断 Prompt：

> **Reentrancy（重入）**：当合约在完成相关状态更新之前执行外部可重入交互，使被调用方能够重新进入合约并观察或修改不一致状态时，判定为 RE 漏洞。仅出现 `balance`、`call` 或其它外部调用关键词，不足以单独判定漏洞；必须结合调用顺序、相关状态读写和保护条件判断。

标签含义：`label=1` 表示根据上述定义建立了 RE 漏洞判断；`label=0` 表示未建立。数据集中的负样本表示“未标注为 RE”，不等价于形式化证明安全。

## 4. 研究问题与假设

**RQ1：** 在 Qwen3.5-9B 上，直接阅读完整源码、固定关键词定位后判断、LLM 生成关键词定位后判断，哪种策略的 RE 检测效果最好？

**RQ2：** 源码复杂度是否改变三种策略的检测效果？

**RQ3：** 关键词策略的误差主要来自“没有定位到相关代码”，还是来自“定位后判断错误”？

本批次是探索性实验。50 条样本只用于观察效果和发现机制，不据此宣称对全部智能合约具有统计普遍性。

## 5. 三种实验方法

### M1：直接 LLM 判断

输入完整的 `prompt_source` 和固定 RE 定义，不提供真实标签、关键词、工具结果或人工结论。Qwen 直接阅读完整源码，输出漏洞判断、简短理由，以及能够支持判断的漏洞行原文和行号。

### M2：固定关键词定位 `balance` + `call` + LLM 判断

先在原始源码上用两个冻结关键词进行确定性定位：

```text
balance
call
```

匹配采用大小写不敏感的字面子串，不自动扩展为 `transfer`、`delegatecall`、`send`、`fallback` 等其它关键词，也不使用正则表达式。每个命中点取前后各 8 行并合并重叠窗口。若没有命中，记录 `no_candidate`。

随后将候选窗口的**原始代码行文本**、行号和固定 RE 定义交给 Qwen，要求输出与 M1 相同的判断、理由和漏洞行原文格式。关键词命中只代表候选定位，不代表 RE 成立。

### M3：LLM 生成关键词 + 确定性定位 + LLM 判断

第一步让 Qwen 根据固定 RE 定义和原始源码生成关键词列表；第二步使用与 M2 完全相同的确定性匹配器和上下文窗口；第三步将命中的候选窗口原文、行号和固定 RE 定义交给同一个 Qwen 判断。

关键词生成阶段只允许输出最多 10 个字符串关键词，不允许输出标签、理由、正则、Cypher、依赖遍历或漏洞结论。关键词生成结果、匹配结果和最终判断分别保存。M3 的关键词可以包含变量名、函数名或 API 名，但必须原样记录，不能事后人工替换。

三种方法的最终检测结果必须分开记录。M2/M3 的最终判断 Prompt、模型、温度、输出格式和候选窗口规则保持一致；M3 额外的关键词生成调用会增加成本和延迟，因此必须单独报告调用次数、Token 数和耗时，不能只比较 F1。

## 6. 统一控制变量

- 模型：固定 Qwen3.5-9B，记录完整运行时模型标识和 digest。
- 输入：同一批 50 条源码、同一源码预处理函数和同一任务定义。
- 推理：`temperature=0`，固定最大输出 Token 数和超时；不使用 few-shot。
- 输出：统一 JSON，至少包含 `label`、`reason`、`evidence_lines` 和 `evidence_text`。`evidence_text` 必须逐字复制输入源码中的原文，不能由模型改写。
- 标签隔离：真实标签只在预测结束后用于评估，不能进入 Prompt、关键词生成或候选筛选。
- 配对执行：三种方法对同一条样本运行；方法顺序按样本随机化并记录。
- 失败处理：解析失败、超时、上下文超限和服务错误均保留为 `no_prediction/<reason>`，不能删除记录或改记为成功。
- 版本冻结：Prompt、关键词表、匹配器、源码哈希和样本清单一旦正式运行，不得根据 50 条结果修改。

## 7. 评价指标

### 7.1 主要检测指标

主要指标为正类 Recall，因为实验的直接目标是检出 RE 漏洞。次要指标包括：

- Precision；
- positive-class F1；
- MCC；
- Accuracy；
- 有效预测覆盖率和各类失败率。

每个指标同时报告总体结果和三个复杂度分层结果，并给出 TP、FP、TN、FN。`no_prediction` 必须保留在覆盖率分母中；主表同时注明有效预测支持集，不能通过删除失败样本提高分数。

### 7.2 定位诊断指标

为回答 RQ3，在 25 条正样本上由人工标注 RE 见证行或见证行区间。若关键词命中窗口与见证行相交（允许 ±2 行），记为定位命中，报告：

- 候选定位 Recall；
- 候选定位 Precision；
- 候选代码压缩率；
- 空候选率和定位失败率。

定位指标是机制诊断，不替代最终漏洞检测指标。M1 也要求输出证据行号，以便与 M2/M3 使用同一行号映射规则比较。

### 7.3 配对比较

三种方法使用同一批样本，优先报告逐条配对差异和 95% bootstrap 区间；可使用 McNemar exact test 做探索性两两比较。由于样本量只有 50，结果应表述为“本批次观察到的差异”，不作稳定性或普遍性结论。

## 8. 执行流程

1. 固定并校验 `sample_manifest.csv`、源码 SHA-256、Prompt 版本和模型 digest。
2. 使用独立的少量 smoke case 检查 JSON 格式、超时和行号映射；smoke case 不计入 50 条正式样本。
3. 对 50 条样本运行 M1、M2、M3，保存原始请求、原始响应、解析状态和最终终态。
4. 用独立脚本复算三种方法的混淆矩阵、指标、覆盖率和定位诊断。
5. 按复杂度分层比较结果，生成 FP/FN、空候选和上下文超限案例清单。
6. 只有在全部工件可复算后，才将结果写入论文或后续汇总表。

## 10. 停止条件与边界

- 任一方法的输入、Prompt、模型或关键词版本发生变化，必须创建新的实验版本。
- 不得因为结果不理想而重新抽样、删除失败记录、调整阈值或修改标签。
- 查询成功或关键词非空不等于语义定位正确；必须分别报告定位质量和最终检测质量。
- 本实验只覆盖 RE 和 Qwen3.5-9B。要推广到 AC、AR、UC 等其它任务，需重新冻结任务定义、关键词和样本。
- 完成 50 条探索性实验后，若观察到稳定趋势，再使用同一协议扩展到全部 398 条 RE 记录。
